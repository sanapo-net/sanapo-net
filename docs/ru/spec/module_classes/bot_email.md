## Общее тех-задание
### Общее для ботов
Подписывается на события в системе необходимые для работы собственно Модуля и на события в системы которые нужны для отправки событий пользователям.
Должен иметь конфиг с информацией о сервере и реквизитах для подключения серверу, адрес первого администратора.
Должен проверять входящую почту раз в 10-20 секунд, **от реализации проверки почты зависит тип Юнита**.
Должен иметь понятие типа пользователей: администратор, пользователь:
- **пользователь** - может подписываться и отписываться на разные виды событий в системе, запрашивать информацию в системе
- **администратор** - иммет права как у пользователя и, дополнительно может добавлять удалять пользователей, отключать пользователям возможность изменять подписку на события, подписывать и отписывать пользователя на события, редактировать список разрешенных типов запрросов для пользователя.


### Темы сообщений
В теме сообщения о событии указывается: `{self.sys_name}: {evt_lvl} {evt_type}: {text}` где:
- `self.sys_name` - имя системы
- `evt_lvl` - уровень важности события
- `evt_type` - тип события
- `text` - краткое описание события, не более 32 символов

В теме сообщения-ответа на запрос указывается: `{self.sys_name}: {req_type}: {text}` где:
- `self.sys_name` - имя системы
- `req_type` - тип запроса на который отвечает бот
- `text` - краткое описание, не более 32 символов (опционально)

Ответы на _бот-сервис-запросы_ (ниже) - в теме сообщения содержат аналогичный текст как сообщения-ответы.

Уровни важности события:
- `HIGH`
- `MEDIUM`
- `LOW`

### Типы бот-сервис-запросов
- **подписка** - `sub`, примеры:
    * `sub all` - подписка на все виды событий
    * `sub some-evt1` - подписка на одно событие
    * `sub (some-evt1 some-evt2)` - подписка на несколько видов событий
- **отписка** - `unsub`, примеры:
    * `unsub all` - отписка от всех событий
    * `unsub some-evt1` - отписка от одного вида событий
    * `unsub (some-evt1 some-evt2)` - отписка от нескольких видов событий
- **регистрация пользователя** - `user-reg`, примеры:
    * `user-reg user@domen.some` - регистрация одного пользвателя
    * `user-reg (user1@domen.some user2@domen.some)` - регистрация нескольких администраторов
- **регистрация администратора** - `admin-reg`, примеры:
    * `admin-reg admin@domen.some` - регистрация одного пользвателя
    * `admin-reg (admin1@domen.some admin2@domen.some)` - регистрация нескольких администраторов
- **дерегистрация пользователя** - `user-unreg`, аналогично регистрации
- **дерегистрация администратора** - `admin-unreg`, аналогично регистрации
**[ ! ]** _дерегистрировать Первого администратора бота невозможно_
- **разрешение пользователю менять подписки** - `user-sub-resolve`, примеры:
    * `user-sub-resolve user@domen.some true` - разрешить менять подписки одному пользователю
    * `user-sub-resolve (user1@domen.some user2@domen.some) false` - разрешить менять подписки нескольким пользователям
- **подписка пользователя** - `user-sub`, примеры:
    * `user-sub user1@domen.some some-evt1` - подписка одного пользователя на один вид событие
    * `user-sub (user1@domen.some user2@domen.some) some-evt1` - подписка нескольких пользвателей на один вид событие
    * `user-sub user1@domen.some (some-evt1 some-evt2)` - подписка одного пользователя на несколько видов событий
    * `user-sub (user1@domen.some user2@domen.some) (some-evt1 some-evt2)` - подписка нескольких пользвателей на несколько видов событий
    * `user-sub user1@domen.some all` - подписка одного пользователя на все виды событий
    * `user-sub all all` - подписка всех пользователей на все виды событий
- **отписка пользователя** - `user-unsub`, аналогично подписке
- **разрешения пользователю на запросы** - `user-req`, примеры:
    * `user-req user1@domen.some some_req` - разрешить пользователю только один вид запроса
    * `user-req user1@domen.some all` - разрешить пользователю все виды запросова
    * `user-req (user1@domen.some user2@domen.some) (some_req1 some_req2)` - разрешить нескольким пользователям несколько видов запросов
- **запреты пользователю на запросы** - `user-unreq`, аналогично разрешениям
- **запрос списка пользователей** - `users`
- **запрос списка администраторов** - `admins`
- **запрос списка подписок пользователя** - `user-sub-list`
- **запрос списка разрешенный запросов пользователя** - `user-req-list`

### Ответы бота на запросы
После обработки запроса от существующего пользователя или администратора бот отправляет реакцию, которая содержит:
- **1 строка** - статус выполнения запроса
- **2 строка** - текст запроса (эхо)
- **3 строка** - опционально: запрошенная информация, может быть несколько строк, может быть изображение

Статусы выполнения запроса:
- `ok` - выполнено
- `no_access` - запрещено выполнение
- `err` - ошибка команды
