# Спецификация: Модульный класс, DbIcmp
 
До этапа тестирования готовых классов (пререлиз) выполняет команды силами импортированных им вспомогательных классов. Для максимальной скорости работы в условиях частой записи каждый файл базы данных развернут как отдельная SQLite БД с включенным режимом WAL (`PRAGMA journal_mode=WAL;`). Это исключает взаимные блокировки при одновременной записи сырых данных и чтении агрегатов.

* Раз в 10 минут от [[buffer_icmp.unit]] приходит команда с агрегированными данными. Юнит сохраняет их пакетной транзакцией в БД [[icmp_10m.database]] с помощью класса [[db_icmp_agr.class]].
* Раз в 10 минут от [[buffer_icmp.unit]] приходит команда с сырыми данными. Юнит сохраняет их в БД [[icmp_raw.database]] с помощью класса [[db_icmp_raw.class]].
* Раз в час накопленные сырые данные из БД [[icmp_raw.database]] юнит агрегирует в записи за час и сохраняет в БД [[icmp_hours.database]].
* Раз в сутки накопленные сырые данные за день из БД [[icmp_raw.database]] юнит агрегирует в записи за сутки и сохраняет в БД [[icmp_days.database]].
* После успешной суточной агрегации в 0:00 юнит закрывает все соединения с [[icmp_raw.database]], физически удаляет файл базы данных (вместе с временными .wal и .shm файлами) и создает его с диска абсолютно чистым. Это гарантирует нулевой размер файла и максимальное быстродействие к моменту прихода первой записи в 0:10.
* Раз в сутки агрегированные данные старее 31 суток юнит удаляет из БД [[icmp_10m.database]].
* Раз в сутки агрегированные данные старее 93 суток юнит удаляет из БД [[icmp_hours.database]].
* Раз в час/сутки/неделю агрегированные данные отправляются в шину сообщений для внешних подписчиков (как минимум для [[analytic.unit]]).
