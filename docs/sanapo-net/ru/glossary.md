# Глоссарий sanapo-net

**Основные сущности**

**Юнит** - Логический объект программы, развёрнутый внутри фреймворка sanapo. Обладает собственным именем, адресом, секретарём, логгером и манифестом. В коде представлен экземпляром класса `BaseUnit`, который управляет жизненным циклом одного **модуля**.

**Модуль** - Python-объект, созданный на основе **модульного класса**. Это главный объект юнита, он реализует бизнес-логику приложения, может иметь методы `start`, `stop`, `step`, подписки на сообщения. В документации _модуль сканера_ означает объект, выполняющий код сканирования.

**модуль (вне контекста архитектуры sanapo)** - Файл с исходным кодом Python (`.py`), лучше заменять на _файл_, чтобы избежать путаницы с модулем-объектом.

**модульный класс** - Python-класс, унаследованный от `BaseModule` (из фреймворка sanapo). На его основе создаётся **Модуль** внутри **Юнита**. Примеры: `ScannerIcmpManager`, `BufferIcmp`.

**вспомогательный класс** - Обычный Python-класс, который **НЕ** наследуется от `BaseModule`. Импортируется и используется внутри **модульного класса** для решения утилитарных задач (рендеринг графиков, работа с сетью). Может находится в одной директории с **модульным классом** или в директории общих вспомогательных классов проекта, если этот вспомогательный класс импортируется несколькими классами. Пример: класс `GraphsRender`, который отрисовывает графики, но сам не является юнитом.

**модульный класс типа UTILITY** - Модульный класс, на основе которого создаётся **юнит типа UTILITY**. Такой юнит не имеет секретаря и псевдоцикла - он используется как вспомогательный объект внутри другого юнита в том же потоке, доступный по прямой ссылке. Основное отличие от **вспомогательного класса** в том, что иммет имя, логгера и доступ к некоторым ресурсам фреймворка.

**псевдоцикл** - Наличие и вызываемость метода `step()` у **модуля**. Этот метод регулярно вызывается агентом-раннером внутри цикла менеджера потока, в котором находится юнит.

**суб-приложение** - Юнит являющийся интерфесным для пользователя, выводит информацию в графический интерфейс или интерфейс сообщений. Может отключаться.

**суб-окно** - Графический образ окна **суб-приложения** которое располагается в рамках общего MDI-интерфейса, меняет размеры за счет действий пользователя, сворачивается, разворачивается, закрывается и так далее.

**Слой (Tier)** - Группа юнитов, которые стартуют и останавливаются совместно в заданном порядке. Номер слоя определяет очерёдность запуска.

**Поток (Thread)** - Изолированный поток операционной системы, в котором работает один или несколько юнитов. Управляется менеджером потоков.

**cообщение (Frame)** - Единица коммуникации между юнитами. Передаётся через брокер сообщений и содержит тип (`CMD`, `EVT`, `RPT`, `SYS`), адресата и полезную нагрузку.

**команда (CMD)** - Тип сообщения, которым один юнит (командир) даёт задание другому юниту (исполнителю). Всегда предполагает ответный рапорт.

**событие (EVT)** - Тип сообщения, который юнит публикует в шину для оповещения всех подписчиков о каком-либо факте (например, завершение сканирования).

**рапорт (RPT)** - Ответное сообщение на команду. Содержит статус выполнения (`DONE`, `INTO_WORK`, `CANT_DO`) и, возможно, результат или причину не выполнения.
