Быстрое обнаружение сетевых сбоев, анализ их масштаба, прогнозирование проблем, визуализация топологии сети и удобные дашборды.

# Ключевые возможности

- **Обнаружение сбоев** – мониторинг доступности устройств по ICMP/TCP в реальном времени с настраиваемыми интервалами.
- **Аналитика и прогнозирование** – автоматическое выявление аномалий, расчёт эталонных профилей поведения сети, обнаружение долгосрочных трендов деградации.
- **Умные дашборды** – динамическое отображение проблемных узлов с контекстом исторических данных.
- **Многоуровневая агрегация** – сырые метрики сворачиваются в 10‑минутные, часовые и суточные срезы; автоматическая очистка устаревших данных.
- **Интерактивные карты сети** – редактор топологии с поддержкой уровней L1/L2/L3, визуальная индикация статусов.
- **Боты‑оповещатели** – Telegram и Email с гибкой системой подписок и команд.
- **Многопоточное сканирование** – эффективный опрос тысяч хостов без блокировки интерфейса.
- **Модульная архитектура** – изолированные юниты, общающиеся через потокобезопасную шину сообщений (фреймворк sanapo).
- **Высокая производительность** – кольцевые буферы в памяти, пакетная запись в SQLite с WAL‑режимом, оптимизированная отрисовка графиков.

# Технологический стек

- **Язык**: Python 3.10+
- **Графический интерфейс**: PySide6 (Qt for Python) — многооконный MDI с темами
- **Базы данных**: SQLite (WAL‑режим), перспектива PostgreSQL/MySQL
- **Ключевые библиотеки**: PySide6, Pillow, colorama, icmplib (позже Pandas, Matplotlib)
- **Фреймворк**: sanapo (собственная разработка) — юниты, потоки, слои, шина сообщений

# Архитектура (кратко)

Проект состоит из изолированных **юнитов**, сгруппированных в слои и запускаемых в определённом порядке. Обмен данными идёт через шину сообщений (команды, события, рапорты). Горячие данные хранятся в кольцевых буферах NumPy, холодные — в агрегированных SQLite‑базах. Приложения‑дашборды общаются только с буферами и готовыми агрегатами, не нагружая сырые хранилища. Подробнее см. [ARCHITECTURE.md](./ARCHITECTURE.RU.md).


# Вклад

Хотите помочь проекту? Ознакомьтесь с [CONTRIBUTING.md](./CONTRIBUTING.md). Мы особенно заинтересованы в помощи с миграцией GUI на PySide6, оптимизацией движка топологии и написанием тестов.
Для написания большинства модуллей не нужно даже понимания многопоточности и асинхронного прогрраммирования, а так же думать об потоко-безопасности сложности передачи информации между модулями, даже если модули находятся на других физических машинах, доступных по сети - эти проблемы решает фреймворк sanapo.
